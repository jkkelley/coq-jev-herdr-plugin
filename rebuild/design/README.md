## 1. What the book is

This directory is the design spec book of the rebuilt factory, step R-03 of `rebuild/factory-rebuild-plan.xml`.
It is the single canonical design (owner ruling C42, 2026-10-14, recorded as D14): SPEC-16, SPEC-17, its 1.1.0 draft and PR 35 are sources, never authority.
Every build ticket is cut from an anchor in this book and from nothing else.
The book is 52 DAG nodes (N-01 to N-52) written as 62 XML volumes and 55 JSON schemas.
Every volume is 1000 lines or fewer, opens with a contents element, names its parent and siblings by pointer, and carries a "many agents at once" section.
Every time in the book is UTC; diagrams are Mermaid; specs are XML; schemas are JSON.

## 2. What is in this directory

- `DESIGN.md` is the owner's read: the whole design in one human-readable file in the owner's fifteen-section format (owner order 2026-10-14 ~17:35Z), pointing into the volumes by anchor; agents read the volumes, the owner reads this.
- `index.xml` is the index volume, generated by `bin/make-index.py`: every node id with its name, group, input record, output record and a pointer to each of its volumes, with line counts.
- `dag.md` is the DAG in Mermaid, every node with its input and output record, the re-entries and the cycle check statement.
- `nodes/<node-id>/spec.xml` is the node volume; `nodes/<node-id>/record.schema.json` beside it is the JSON schema of every record the node reads or writes.
- `shared/` holds the volumes every node points into: `status-codes.xml` (the status code map), `principles.xml`, `seat-contract.xml`, `state-store.xml` with `state-store.schema.json`, `failure-cases.xml`, `rejected-with-reason.xml`, `cut-over.xml` (the one GOFACTORY cut-over order), `command-center.xml` (the Factorio map), and two generated files, `record-kinds.xml` and `cleanup-registry.json` with its schema.
- `schema/volume.xsd` is the one XSD family every volume validates against.
- `check.sh` validates the whole book; `bin/check-book.py` is the checker behind it.
- `bin/make-index.py`, `bin/make-kinds.py` and `bin/registry.py` generate `index.xml`, `shared/record-kinds.xml` and `shared/cleanup-registry.json`; never edit those three by hand, edit the volumes and regenerate.
- `bin/dag-check.py` checks that `dag.md` agrees with itself and is acyclic; `bin/check-examples.py` (C22) validates every JSON example in the volumes and in `DESIGN.md` against the schema it names; `bin/test-checks.py` proves every check fires on a mutated copy of the book.

## 3. How to read one volume

Read one volume at a time, never the whole book.

1. Find the node in `index.xml` (element `nodes`) or in `dag.md` section 3, and follow its spec pointer.
2. Read the volume's `contents` element first; every entry names an id in the same file, in order.
3. Read `input` and `output`: the record that starts the node and the record that ends it. A seat on a node exists only between the two.
4. Read `waits`, `retries` and `many-agents` for how the node behaves when something is slow, fails, or is claimed twice.
5. Follow a pointer only when you need it: `path` plus `anchor`, or `href="file#anchor"`, resolved from the volume's directory, then the book root, then the repository root.
6. Status codes resolve in `shared/status-codes.xml`; record kinds in `shared/record-kinds.xml`; state paths and their cleanup in `shared/cleanup-registry.json`.

## 4. How to run check.sh

From the repository root:

```bash
rebuild/design/check.sh
```

Exit 0 means every check passed, 1 means at least one failed (one `FAIL <check> <file> <detail>` line each), 2 means the checker could not run.
The XSD validator is the python `xmlschema` module when importable, else `uv run --with xmlschema`, else `xmllint`.
Set `COQ_CHECK_NOTES=1` to print the NOTE lines (external sources, other-branch citations, planned files).
The checks are C01 to C22, listed at the top of `bin/check-book.py` with the same ids as `nodes/N-46/spec.xml#checks`.
To prove every check still fires, run `uv run --with xmlschema --with jsonschema python3 -I rebuild/design/bin/test-checks.py`.

## 6. R-03 is a gate the owner closes

R-03 ends when the owner reads the book and closes the gate.
No seat and no architect closes it: the landing seat opens the pull request and does not merge it.
Until the owner closes R-03, no build ticket is cut from this book.

## 7. Artifacts and cleanup

Nothing the checker or the generators write lands in the repository; scratch and logs go under the session scratchpad or `$COQ_STATE`.
Every state path a volume names has an entry in `shared/cleanup-registry.json` with the verb `line/bin/cleanup.sh --entry <id>`, which the N-45 build ticket creates.
